# Implementation Plan: Design Session Management (2D/3D Editor)

**Branch**: `001-design-editor` | **Date**: 2026-06-01 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `.specify/specs/029-design-editor/spec.md`

**Note**: Codebase research confirms the design editor is already substantially implemented. This plan focuses on audit, gap-filling, and lifecycle enforcement.

## Summary

Deliver a browser-based 2D/3D packaging design editor enabling customers to create, preview, export, and submit custom packaging designs with a formal lifecycle (Draft → Submitted → In Review → Approved/Rejected → In Production). The editor leverages existing Fabric.js 2D canvas and Three.js 3D preview infrastructure, with additions for design lifecycle state enforcement, access control integration, brand kit management, and export enhancements.

**Research finding**: The codebase already contains a fully functional design editor with Fabric.js 2D editing, Three.js 3D preview, a Zustand-based design store with undo/redo, pre-press validation, and 60+ templates. The primary work items are: (1) formalizing the design lifecycle state machine across backend and frontend, (2) enforcing access control rules per lifecycle stage, (3) completing the brand kit feature, and (4) adding AI/EPS vector export support.

## Technical Context

**Language/Version**: TypeScript 5.x (strict), Node.js LTS (20.x)

**Primary Dependencies**:
- **Backend**: Fastify ^4.25 + Prisma ^5.9 + Zod ^3.22 + BullMQ ^5.4 + ioredis ^5.3
- **Frontend**: Next.js 14 (App Router) + React 18 + Zustand ^4.5 + Fabric.js ^5.3 + Three.js ^0.160 + @react-three/fiber ^8.15 + @react-three/drei ^9.92
- **Export**: pdfkit ^0.14 + jspdf ^3.0 + sharp ^0.33
- **Auth**: next-auth ^5 + jsonwebtoken ^9.0 + bcrypt ^5.1

**Storage**:
- **Primary DB**: PostgreSQL 16 via Prisma ORM
- **Session cache**: Redis via ioredis (design session state, auto-save buffer)
- **File storage**: S3-compatible (AWS S3 / Cloudflare R2) via @aws-sdk/client-s3
- **Queue**: BullMQ on Redis (async pre-press checks, export jobs)

**Testing**:
- **Backend**: Vitest (unit) + Supertest (integration) — 80% coverage target per constitution
- **Frontend**: Vitest + React Testing Library (component) + Playwright (e2e for critical flows)
- **Existing patterns**: `backend/src/modules/pricing/pricing.service.test.ts`

**Target Platform**: Desktop web browsers (Chrome, Firefox, Safari, Edge) with WebGL support. Mobile/tablet explicitly out of scope for v1 per spec assumptions.

**Project Type**: Full-stack web application (monorepo: backend API + frontend SPA)

**Performance Goals**:
- 3D preview updates within 2 seconds of any design change (spec SC-002)
- <200ms p95 API response for reads, <500ms p95 for writes (constitution)
- First Paint <1.5s on simulated 3G (constitution)
- Auto-save persists within 30s of last edit

**Constraints**:
- All code TypeScript, `any` prohibited (constitution)
- Conventional Commits enforced (constitution)
- JWT auth on all endpoints except health/auth (constitution)
- No texture/material creation inside render loop (existing architecture constraint)
- Design session data <5MB per session (existing architecture constraint)
- WebGL required for 3D preview (documented assumption)

**Scale/Scope**: Existing production system with ~19 Prisma models covering the full packaging lifecycle. This feature is additive to existing modules, not greenfield.
